## Summary

Successfully implemented the stale runtime reference fixes as specified in `docs/fixes/023-effect-runtime-stale-references.md`. Key changes:

**Root Cause**: Components and services were capturing `getMainRuntime()` at mount/initialization time, creating stale references to the old runtime after `reinitializeRuntime()` was called during wallet setup.

**Solution Applied**: Modified all components and services to call `getMainRuntime()` at the point of Effect execution, ensuring they always use the current runtime instance with the latest service configuration.

**Critical Fix**: The DVM service `Kind5050DVMServiceImpl` was using mock `SparkServiceTestLive` instead of real `SparkServiceLive` because its long-running payment checking fiber was using stale service references from the initial runtime. Now it gets fresh services on each iteration.

**Expected Result**: After wallet initialization, DVM operations should now use the real `SparkServiceLive` and create real Lightning Network invoices instead of mock invoices with "mock_invoice_" prefixes.
