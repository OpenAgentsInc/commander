# SWE-Bench Phase 5: Task-Specific Docker Environments

**Date**: 2025-05-31  
**Time**: 12:36  
**Task**: Implement Phase 5 - Refining Docker Image Building for Task-Specific Environments

## Objective

Modify the Docker image building process and evaluation script to install task-specific dependencies and use appropriate Python versions, enabling correct test execution within dynamically built containers.

## Implementation Log

### 1. Updated Dockerfile Template

✅ **Updated `assets/dockerfiles/swe_bench_task.Dockerfile`**

Key changes:
- Multi-stage build with `conda_base`, `task_env`, and `instance` stages
- Added arguments for Python version (`PYTHON_VERSION_ARG`) and conda environment name (`CONDA_ENV_NAME_ARG`)
- Create task-specific conda environment with specified Python version
- Set `SHELL ["/bin/bash", "-lc"]` to ensure conda environment is active for RUN commands
- Added dependency installation step that looks for and installs from:
  - `environment.yml` (conda env update)
  - `requirements.txt` (pip install)
  - `setup.py` (pip install -e .)
- All dependency installation happens AFTER cloning the repository

### 2. Updated DockerBuildManagerServiceImpl

✅ **Modified `src/services/swe_bench_harness/DockerBuildManagerServiceImpl.ts`**

Key changes:
- Added logic to derive Python version from `task.version` if it matches pattern `X.Y` or `X.Y.Z`
- Falls back to `SWE_BENCH_DEFAULT_PYTHON_VERSION` config or "3.8" as default
- Generate conda environment name from sanitized repo name and version (e.g., `django__django-3_2`)
- Get base image name from `SWE_BENCH_BASE_IMAGE_NAME` config
- Updated `BuildContextResult` interface to include:
  - `pythonVersion`
  - `condaEnvName`
  - `baseImageName`

### 3. Updated SWEBenchLifecycleServiceImpl

✅ **Modified `src/services/swe_bench_harness/SWEBenchLifecycleServiceImpl.ts`**

Key changes:
- Pass new build arguments to `docker.buildImage`:
  - `SWE_BENCH_BASE_IMAGE_ARG`
  - `PYTHON_VERSION_ARG`
  - `CONDA_ENV_NAME_ARG`
- These values come from the enhanced `buildContext` object

### 4. Updated SWEBenchEvaluationScriptServiceImpl

✅ **Modified `src/services/swe_bench_harness/SWEBenchEvaluationScriptServiceImpl.ts`**

Key changes:
- Updated `eval.sh` script to use `CONDA_ENV_NAME` environment variable from Docker
- Added proper conda initialization: `source /opt/miniconda/etc/profile.d/conda.sh`
- Added Python version and environment verification after activation
- Changed error message to specify "Conda activation failed in eval.sh"

### 5. Updated ConfigurationServiceImpl

✅ **Modified `src/services/configuration/ConfigurationServiceImpl.ts`**

Key changes:
- Added `SWE_BENCH_BASE_IMAGE_NAME` config (same value as deprecated `SWE_BENCH_BASE_IMAGE`)
- Added `SWE_BENCH_DEFAULT_PYTHON_VERSION` config with default value "3.8"
- These configs are used by DockerBuildManagerServiceImpl

## Summary

The implementation now supports task-specific Docker environments with:
1. **Dynamic Python version selection** based on task.version
2. **Task-specific conda environments** named after the repo and version
3. **Automatic dependency installation** from environment.yml, requirements.txt, or setup.py
4. **Proper conda environment activation** in eval.sh using Docker environment variables

The system is now much better aligned with SWE-Bench's requirement for task-specific environments, which should significantly improve test execution success rates.
