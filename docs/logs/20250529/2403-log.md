# Claude Code CLI Conversation History Fix - Implementation Log

## Overview
Implementing fix for Claude Code CLI not receiving full conversation history including tool calls/results after page refresh.

## Problem Summary
- After page refresh, Claude Code CLI only receives first message instead of full conversation history
- Tool calls and results are stripped out during formatting
- CLI restarts task instead of continuing with context

## Starting Implementation

### Step 1: Check current formatter implementation
First, let's examine the current `formatMessagesForClaudeCli` function to understand what needs to be enhanced.

**Current Implementation Analysis:**
- Only uses `message.content` field, ignoring `parts` array
- Strips out all tool call and tool result information
- Results in loss of context when CLI receives the prompt

### Step 2: Check AgentChatMessage type to understand parts structure

**Finding:** The AgentChatMessage type doesn't have a `parts` array as mentioned in the instructions. Instead, it has:
- `tool_calls` array for assistant messages that call tools
- `tool_call_id` for tool response messages
- Different roles including "tool" for tool responses

This is different from what the instructions describe. Let me check the UI message types which might have the `parts` structure.

**Found it!** The `ChatMessage` interface in `useCoderChat.ts` has the `parts` array structure:
- Text parts: `{ type: 'text'; text: string }`
- Tool call parts: `{ type: 'tool_call'; id: string; name: string; input: Record<string, any> }`
- Tool result parts: `{ type: 'tool_result'; tool_use_id: string; content: any; isError?: boolean }`

Now I need to understand how these UI messages are converted to AgentChatMessage format when sent to the provider.

**Key Finding:** In `useCoderChat.ts` line 370-374, messages are mapped to a simple format for the API:
```typescript
const apiMessages = currentMessages
  .filter(m => m.role !== 'system')
  .concat(userMessage)
  .map(m => ({ role: m.role, content: m.content }));
```

**This is the problem!** The `parts` array is completely ignored when sending messages to the API. Only the `content` field is sent, which means all tool call/result structure is lost.

### Step 3: Check how the provider receives and formats these messages

Found `ClaudeCodeAgentLanguageModelLive.ts`:
- Line 69: It parses messages from `options.prompt` which contains `{ messages: [...] }`
- Line 70: Calls `formatMessagesForClaudeCli` to format messages for the CLI
- This is where the problem occurs - the formatter only uses `content` field

Now I need to enhance both:
1. The formatter to handle `parts` array
2. The message passing from `useCoderChat` to include `parts`

### Step 4: First, let's fix the message passing in useCoderChat to include parts

✅ Fixed `useCoderChat.ts` to include the `parts` array when sending messages to the API.

### Step 5: Now enhance the formatMessagesForClaudeCli function to handle parts

After analyzing the code structure, I found that:
1. `useCoderChat` has already been modified to include `parts` array when sending messages
2. The UI messages have a `parts` array structure, but AgentChatMessage uses different fields
3. Need to update the formatter to handle both the legacy format and the new parts array

The challenge is that the messages coming from useCoderChat have a `parts` array, but the AgentChatMessage type expects:
- `tool_calls` array for assistant messages
- `tool_call_id` for tool responses  
- Role "tool" for tool responses

Let me enhance the formatter to handle both formats.

### Step 6: Enhanced the formatMessagesForClaudeCli function

✅ Updated the formatter in `claudeFormatters.ts` to:
- Handle messages with `parts` array (from UI)
- Format tool calls as JSON objects for the CLI
- Format tool results as JSON objects
- Handle legacy format with tool_calls array
- Extract and handle system prompts separately

### Step 7: Updated ClaudeCodeAgentLanguageModelLive

✅ Modified to:
- Extract system message from the message array
- Pass only user/assistant messages to the formatter
- Include systemPrompt in cliParams for proper CLI flag handling

### Step 8: Issue with main-claude-websocket.ts

Found that `main-claude-websocket.ts` has its own inline formatter `formatMessagesForClaudeCli_main` that doesn't handle parts array. This means the enhanced formatting is not being used by the main process.

The issue is that:
1. `ClaudeCodeAgentLanguageModelLive` receives messages with parts from useCoderChat
2. It passes `params.messages` to main process via IPC
3. main-claude-websocket.ts uses its own formatter that ignores parts

Need to fix this by either:
- Option A: Have main-claude-websocket.ts use the formatted prompt from the renderer
- Option B: Update main-claude-websocket.ts formatter to handle parts

### Step 9: Discovery - useCoderChat bypasses AI service providers

Found that `useCoderChat` is NOT using the AI service providers (like ClaudeCodeAgentLanguageModelLive). Instead, it directly calls the Claude Code IPC API. This means:
- The enhanced formatter in `claudeFormatters.ts` is not being used by the Coder pane
- The main-claude-websocket.ts receives messages directly from useCoderChat
- Need to update the inline formatter in main-claude-websocket.ts

### Step 10: Updated main-claude-websocket.ts formatter

✅ Enhanced the `formatMessagesForClaudeCli_main` function to:
- Handle messages with `parts` array (from UI)
- Format tool calls as JSON objects (matching CLI's expected format)
- Format tool results as JSON objects
- Preserve the same structure as the enhanced formatter

The formatter now properly serializes:
- Text parts as plain text
- Tool calls as: `{"type":"tool_use","id":"...","name":"...","input":{...}}`
- Tool results as: `{"type":"tool_result","tool_use_id":"...","content":"...","is_error":false}`
