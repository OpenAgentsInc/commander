# Tool Execution Database Persistence Fix

## Summary

The core issue is that `tool_executions` records are not being successfully inserted into the database by the `claude-bridge-service.js`. This causes the subsequent `updateToolCallResult` operations to fail because they can't find the records to update, leading to missing tool results on page refresh.

## Implementation Steps

### 1. Enhanced saveToolCall in claude-bridge-service.js

Updated the `saveToolCall` case to add robust logging, error checking, and verification:

- Added parameter validation
- Added `ON CONFLICT(id) DO NOTHING` to make inserts idempotent
- Added verification SELECT after INSERT to confirm the record exists
- Added parent message existence check if insert fails
- Enhanced logging throughout

Key changes:

### 2. Enhanced updateToolCallResult in claude-bridge-service.js

Updated to use consistent pattern with better logging:

- Added full result logging to understand PGLite response structure
- Check multiple possible properties for affected rows (affectedRows, changes, rowCount)
- Added verification SELECT after successful UPDATE
- Added existence check if UPDATE affects 0 rows

### 3. Updated main-claude-websocket.ts helper functions

Enhanced both `saveToolCallToDatabase` and `updateToolCallResultInDatabase`:

- Added unique request IDs to match responses correctly
- Added 5-second timeout for database operations
- Check `response.result.success` explicitly
- Log detailed error messages in main process
- Better error handling with typed errors

Key changes:
```typescript
async function saveToolCallToDatabase(toolCall: any): Promise<void> {
  const requestId = `db-save-toolcall-${Date.now()}-${Math.random().toString(36).substring(2,9)}`;
  
  // Check response.id matches requestId
  if (response.id === requestId) {
    if (response.type === 'db_result' && response.result && response.result.success) {
      console.log(`[Main Process] Tool call ${toolCall.id} reported as saved by bridge.`);
      resolve();
    } else {
      const errorMessage = response.error || (response.result && response.result.error) || 'Unknown error';
      console.error(`[Main Process] Bridge service FAILED to save tool call ${toolCall.id}: ${errorMessage}`);
      reject(new Error(`Bridge failed to save tool call: ${errorMessage}`));
    }
  }
}
```

## ROOT CAUSE FOUND - TIMING ISSUE

The real issue is a **race condition** in the message processing flow:

1. **During streaming**:
   - Assistant message with tool_use arrives
   - Tool results arrive as user messages with tool_result
   - We try to UPDATE tool_executions with the result
   - **BUT**: Tool calls haven't been saved to DB yet!

2. **After streaming completes**:
   - Assistant message is saved to database
   - Tool calls are extracted and saved to tool_executions table
   - But by this time, the tool results have already failed to save

The fix needs to ensure tool calls are saved to the database IMMEDIATELY when they arrive in the stream, not after the entire message completes.

### Evidence from logs:
- Line 164: `[Main Process] Attempting to save tool result for toolu_01WQgYWpYXXHQaL7fUfijBLV`
- Line 179: `[DB Bridge] ERROR: No tool_execution record found with id: toolu_01WQgYWpYXXHQaL7fUfijBLV to update.`
- Line 647: `[DB Bridge] SUCCESS (Verified): Tool call toolu_01WQgYWpYXXHQaL7fUfijBLV saved.` (AFTER stream complete)

The tool result tries to update a record that doesn't exist yet because tool calls are saved too late!
