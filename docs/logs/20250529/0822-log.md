# Fix Timing Issue: Save Tool Calls Immediately During Streaming

## Problem Summary

The root cause of tool results not persisting is a race condition:
- Tool results arrive and try to UPDATE tool_executions records
- But tool calls are only saved to DB AFTER the entire assistant message completes
- This causes tool results to fail updating non-existent records

## Implementation Plan

1. Modify `main-claude-websocket.ts` to save tool calls immediately when they arrive in the stream
2. Keep the existing logic for collecting tool calls for the final message save
3. Ensure assistantMessageId is available when processing tool_use parts

## Implementation

### Step 1: Examine current implementation

Found the critical sections where tool_use parts are processed at lines 388 and 498. Tool calls are being collected but only saved to database after stream completes (lines 554-568 and 619-633).

### Step 2: Implement immediate tool call saving

Added immediate database saving logic to both tool_use processing blocks:

1. **First occurrence (line 388)**: Inside `claude_stream_chunk` handler for assistant messages
   - Added code after pushing to toolCalls array
   - Creates toolExecutionData object with all required fields
   - Calls saveToolCallToDatabase immediately with fire-and-forget pattern
   - Includes error handling and logging

2. **Second occurrence (line 498)**: Inside legacy `data` handler for assistant messages
   - Same implementation as above, using toolExecutionData2 to avoid variable conflicts
   - Ensures both streaming paths save tool calls immediately

### Key aspects of the implementation:

- Tool calls are saved with status "pending" immediately when they arrive
- Uses the same data structure as the delayed save logic
- Includes proper error handling without blocking the stream
- Maintains the existing toolCalls array for the final message save
- assistantMessageId is available in both contexts (initialized on line 346, updated on line 375)

### Step 3: Verify the fix

The implementation ensures:
1. Tool calls are saved to DB as soon as they arrive in the stream
2. Tool results that arrive shortly after will find the records to update
3. The existing logic for final message save remains intact (avoiding duplicate inserts due to ON CONFLICT clause)

With this fix, the timing issue should be resolved:
