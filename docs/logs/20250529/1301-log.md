# Claude Code Chat History Fix - Implementation Log

## Overview
Fixing the issue where Claude Code integration only considers the initial message of a loaded chat history, ignoring subsequent interactions.

## Changes Made

### 1. Updated claudeFormatters.ts for Proper CLI Formatting
- Modified `formatMessagesForClaudeCli` to:
  - Filter out system messages (handled via `--system-prompt` flag)
  - Map roles correctly: 'user' → 'Human:', 'assistant' → 'Assistant:'
  - Append 'Assistant:' at the end if the last message is from user
  - Join messages with '\n\n' for proper formatting

### 2. Updated useCoderChat.ts to Pass System Prompt
- Modified `sendMessage` function to:
  - Extract system message content from current messages
  - Provide fallback default if no system message exists
  - Pass `systemPrompt` parameter to `streamChat` API call
  - This ensures system context is properly sent to Claude CLI

### 3. Refactored main-claude-websocket.ts for Proper Message Handling
- Replaced old conversation building logic with new approach:
  - Now receives `params.systemPrompt` explicitly from useCoderChat
  - Added inline `formatMessagesForClaudeCli_main` function that matches the one in claudeFormatters.ts
  - Uses formatter to properly format conversation history with Human:/Assistant: prefixes
  - Passes system prompt via `--system-prompt` CLI flag instead of including in messages
  - Added support for additional CLI parameters (model, temperature, max_tokens)
  - Fixed database session creation to use `params.systemPrompt` instead of searching in messages
  - Updated user message saving to use `chatMessagesForPrompt` variable

## Key Changes Summary
- System messages are now handled separately via `--system-prompt` flag
- Conversation history is properly formatted with Human:/Assistant: prefixes
- Full conversation context is preserved when loading chat history
- CLI arguments are built correctly with all necessary parameters

## TypeScript Fixes
- Fixed type error in `main-claude-websocket.ts` by properly typing `args` array as `string[]`
- All tests now pass with `pnpm run t`

## Implementation Complete
The fix ensures that when loading a chat history and sending a new message, the Claude Code CLI receives:
1. The complete formatted conversation history (Human:/Assistant: format)
2. The system prompt via the `--system-prompt` flag
3. All necessary parameters (model, temperature, max_tokens)

This resolves the issue where Claude would respond as if it's the first turn, ignoring previous interactions in the loaded chat history.
