## Root Cause Analysis

### Issue 1: Log File Not Created
The utility process exits before creating the log file, suggesting:
- Module loading failure (likely `node-pty`)
- Early crash in utility process initialization
- Permission issues in utility process context

### Issue 2: Exit Code 1
Generic failure code without stderr output indicates:
- JavaScript syntax error
- Missing module in utility process context
- Environment setup failure

## Key Discoveries

### Electron utilityProcess Limitations
1. **Native Module Access**: May not support native modules like `node-pty`
2. **Module Resolution**: Different module paths than main process
3. **Environment Context**: More restricted than expected

### Network Access Hypothesis
While `respondToAuthRequestsFromMainProcess: true` enables network access, the utility process may still be too restricted for:
- Dynamic native module loading
- Complex subprocess operations
- PTY emulation

## Recommendations

### Immediate Action: Debug Wrapper
Replace complex wrapper with minimal version to isolate issue:
1. Remove node-pty dependency
2. Add basic logging to console/file
3. Test simple spawn instead of PTY
4. Verify basic message passing works

### If utilityProcess Fails: External Service
The external service bridge approach becomes more attractive:
- Full Node.js environment
- No Electron restrictions
- Proven to work with node-pty
- Complete network access

The utilityProcess approach shows promise but faces challenges with:
1. Native module loading (node-pty)
2. Limited debugging visibility
3. Restricted execution environment

Next step is to create a minimal debug wrapper to verify basic utilityProcess functionality before proceeding with full implementation or pivoting to external service approach.
