## Post-Implementation Fixes

### Issue 1: NIP90 Module Loading in Renderer
- **Problem**: NIP90AgentLanguageModelLive was being loaded in renderer process, causing "\_\_dirname is not defined" error
- **Solution**: 
  - Commented out NIP90Provider export from providers/index.ts
  - Commented out providers export from ai/index.ts  
  - Added runtime check to prevent NIP90AgentLanguageModelLive from loading in renderer
  - Changed ChatOrchestratorService to use dynamic imports for NIP90

### Issue 2: PGLite Database URL Format
- **Problem**: PGLite initialization failing with "The URL must be of scheme file"
- **Solution**: Used NodeFS from @electric-sql/pglite/fs for proper file system access in Electron

### Issue 3: Electron Import in Renderer Process
- **Problem**: PGLiteService (which imports electron) was being exported from db/index.ts and loaded in renderer
- **Solution**: 
  - Removed PGLiteService and DatabaseServiceImpl exports from db/index.ts
  - Updated db-listeners.ts to import these directly from their source files
  - This prevents electron-dependent modules from being bundled for the renderer

### Issue 4: Database IPC Calls Failing
- **Problem**: When trying to load chat history, getting "DatabaseError: IPC getMessagesForSession failed"
- **Root Cause**: PGLite has compatibility issues with Electron's file system restrictions
- **Solution**: Move database operations to the WebSocket bridge service
  - Added PGLite initialization to claude-bridge-service.js
  - Created database operation handlers in the bridge service
  - Created DatabaseServiceWebSocketProxy to route DB calls through WebSocket
  - Updated main process IPC handlers to use the WebSocket proxy
  - Database now runs in pure Node.js environment without Electron restrictions

### Issue 5: Infinite Loop in Chat History Loading
- **Problem**: useAgentChat hook causing infinite re-renders when loading history
- **Solution**: Used useMemo for system message instance to maintain stable reference

### Issue 6: WebSocket Proxy in Renderer
- **Problem**: DatabaseServiceWebSocketProxy using Node.js 'ws' module in renderer
- **Solution**: Updated to use browser's built-in WebSocket API:
  - Removed `require('ws')` 
  - Changed from `.on()` event handlers to browser WebSocket event properties
  - Fixed MessageEvent typing for browser compatibility

### Issue 7: Main Process Database Calls
- **Problem**: main-claude-websocket.ts still using Effect/database runtime
- **Solution**: Replaced all database runtime calls with WebSocket helpers:
  - Created helper functions: saveSessionToDatabase, saveMessageToDatabase, saveToolCallToDatabase, updateSessionInDatabase
  - Updated all database operations to use WebSocket instead of Effect
  - Added updateSession handler to bridge service
  - Removed all Effect/DatabaseService dependencies from main-claude-websocket.ts

### Issue 8: Content Security Policy Blocking WebSocket
- **Problem**: CSP directive blocking connections to ws://localhost:45671
- **Solution**: Added `ws://localhost:45671` to connect-src in index.html CSP

### Issue 9: Timestamp Type Mismatch
- **Problem**: Unix timestamp integer being passed to PostgreSQL TIMESTAMP column
- **Solution**: Updated updateSession handler to use `to_timestamp()` function to convert Unix timestamp to PostgreSQL timestamp

### Issue 10: SQL Query Syntax Error
- **Problem**: PGLite doesn't support parameterized queries with `?` placeholders
- **Solution**: Updated all database queries to use string interpolation with exec() instead of query()
  - Fixed getMessagesForSession query
  - Fixed getSession query

### Issue 11: Session ID Mismatch
- **Problem**: Messages saved but not showing in UI due to session ID mismatch
- **Investigation**: Added logging to track session ID flow between renderer and main process
- **Root Cause**: The ChatOrchestratorService was creating a custom IPC implementation for claude_code that wasn't passing the sessionId parameter
- **Solution**: Updated the orchestrator's claude_code implementation to pass sessionId in both streamText and generateText methods

### Issue 12: Messages Disappearing from UI
- **Problem**: Messages were being saved to database but disappearing from UI immediately
- **Root Cause**: The history loading effect was overwriting the messages array even when loading returned 0 messages
- **Solution**: Updated history loading to only set messages if historical messages were actually found, preserving current messages for new sessions
