## Root Cause Identified - 07:30

The debugging revealed the issue:

1. **Tool results are never saved to database**:
   - Tool calls are saved with status "pending" when the assistant message completes
   - Tool results (from Task execution) are never saved to update the tool_executions table
   - The `result_json` field remains null in the database

2. **Why it works before refresh**:
   - The UI builds the parts array in memory during streaming
   - Tool results are added to the parts array as they stream in
   - This in-memory state is lost on refresh

3. **Why it breaks after refresh**:
   - Database only has tool calls (no results)
   - Code correctly identifies no tool results: "No tool result found for toolu_..."
   - UI shows tool calls without their results

## Solution Needed

The Task tool executes within Claude's process, and its results come as part of Claude's text response, not as separate tool_result messages. We need to either:

1. Parse Claude's response to extract tool results and save them
2. Modify the streaming handler to capture and save tool results when they arrive
3. Change how we display tool calls that have no results (show as "pending" or hide them)

## Solution Implemented - 07:35

After analyzing the logs, I discovered that tool results DO come back from Claude, but as a `user` message with `tool_result` content. This is the standard Claude API pattern for tool execution results.

### Changes Made:

1. **Added tool result saving in main-claude-websocket.ts**:
   - When a `user` message with `tool_result` content arrives, update the database
   - Created `updateToolCallResultInDatabase` function to update tool executions
   - Extract text content from tool results and save to `result_json` field

2. **Cleaned up debug logging**:
   - Removed verbose logging from CoderPane.tsx
   - Kept essential error logging

### How it works now:

1. Assistant sends tool_use → saved as "pending" tool execution
2. Claude executes the tool (e.g., Task agent)
3. Claude sends back a user message with tool_result
4. We capture this and update the tool execution with the result
5. On refresh, tool results are loaded from database and displayed correctly

The fix ensures that tool results persist across page refreshes, maintaining the same visual order and content as before the refresh.
